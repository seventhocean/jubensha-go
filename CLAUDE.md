## Project Overview

bbs-go is a self-hosted community platform (forums, Q&A, articles) with a Go backend and React frontend, licensed under GPLv3. It supports MySQL and SQLite, with built-in i18n (en-US, zh-CN).

## Build and Development Commands

```bash
# Core workflow
make build          # Build SPA + Go binary (embedded SPA)
make build-go       # Build Go binary only (builds SPA first if missing)
make run            # Build SPA + run Go server
make run-go         # Run Go server (builds SPA first if missing)
make test           # Run Go tests
make check          # Go tests + web typecheck + web lint

# Release
make release        # Cross-compile for linux/macOS/Windows (amd64/arm64)
make build-linux    # Linux/amd64 only

# Web frontend (cd web or use make targets)
make web-dev        # Start web dev server (react-router dev)
make web-build-spa  # Build SPA for embedding
make web-build-ssr  # Build SSR output
make web-typecheck  # TypeScript type checking
make web-lint       # ESLint
make web-install    # pnpm install --frozen-lockfile

# Code generation
make generator              # Run code generator
make generate-permissions   # Generate permission definitions

# Cleanup
make clean          # Remove Go binaries
make clean-web      # Remove web build output
```

## Architecture

### Backend (Go)

**Entry point**: `main.go` → `server.Init()` (config, logger, locales, DB, migrations) → `server.NewServer()` (Gin router on configured port).

**Three-layer pattern** — handlers call services, services call repositories:
- `internal/repositories/` — Data access. Each file exports a singleton (e.g. `ArticleRepository`). Methods take `*gorm.DB` as first parameter (obtained via `sqls.DB()`).
- `internal/services/` — Business logic. Each file exports a singleton (e.g. `ArticleService`). Services coordinate repositories, handle transactions, emit events.
- `internal/handlers/api/` — Public API handlers (`/api/...`)
- `internal/handlers/admin/` — Admin dashboard API handlers (`/api/admin/...`), guarded by `AdminMiddleware`
- `internal/handlers/render/` — Response builder functions that transform models into API-friendly JSON shapes

**Router** (`internal/server/router.go`):
- `/api/...` routes — wrapped with `InstallMiddleware` + `AuthMiddleware`
- `/api/admin/...` routes — additionally wrapped with `AdminMiddleware`
- SPA served from embedded `web/build/spa` via `ginx.HandleSPA`
- `/sitemap.xml` — redirects to generated sitemap URL

**Event system** (`internal/pkg/event/`): Async pub-sub using an `ants` goroutine pool. Events are Go structs sent via `event.Send(e)`. Handlers register with `event.RegHandler(reflect.TypeOf(EventType{}), handlerFunc)`. Event handlers live in `internal/services/eventhandler/`.

**Config** (`internal/pkg/config/`): Reads `bbs-go.yaml` via Viper. Env var overrides with `BBSGO_` prefix. `config.Instance` is the global config singleton.

**Database**: GORM with table prefix `t_`. Models listed in `internal/models/models.go` `Models` slice — used for AutoMigrate. Supports MySQL and SQLite (pure Go driver via `glebarez/sqlite`). Connection managed via `github.com/mlogclub/simple/sqls` (global `sqls.DB()`).

**Install flow**: Web wizard at `/install` (handled by SPA route `install.tsx`). Backend install endpoints at `/api/install/*` (unguarded by InstallMiddleware). Install process writes `bbs-go.yaml`, runs AutoMigrate + data migrations, creates admin user, initializes default config.

**Search**: Bleve full-text search (`internal/pkg/search/`). Index rebuilt via admin API `/api/admin/search/reindex`. Index path configured in `Search.IndexPath`.

**Scheduler** (`internal/scheduler/cron.go`): Cron jobs via `robfig/cron`. Currently only daily sitemap generation at 4 AM. Only starts in production mode.

**Permissions** (`internal/permissions/`): RBAC system with permission codes like `dashboard.workspace.overview`. Generated by `cmd/generator/permissions/main.go`. Role-based access checked in admin handlers.

**Migrations** (`migrations/`): Numbered Go migration scripts executed sequentially via `migrations.Migrate()`. Each uses `golang-migrate` to register ups and downs.

### Frontend (web/)

- **Framework**: React Router v7 with SSR. SPA mode is the production default (built with `BBSGO_WEB_SPA=true`).
- **Package manager**: pnpm 10.30.2+ with `--frozen-lockfile`
- **Routing**: File-based routes in `web/app/routes/` (React Router conventions)
- **API client**: `web/lib/api/client.ts` — central HTTP client. Separate API modules in `web/lib/api/` (topics.ts, users.ts, auth.ts, etc.)
- **Server actions**: `web/lib/actions/` — SSR data loading
- **Components**: `web/components/` organized by domain (topic, article, comment, user, dashboard, editor, etc.)
- **UI library**: `@base-ui/react` (unstyled primitives)
- **Editor**: TipTap rich text editor

### Key Dependencies

- `github.com/mlogclub/simple` — Internal framework providing web helpers, SQL utilities, common functions
- `github.com/gin-gonic/gin` — HTTP framework
- `gorm.io/gorm` — ORM
- `github.com/blevesearch/bleve/v2` — Full-text search engine
- `github.com/panjf2000/ants/v2` — Goroutine pool for async event processing
- `github.com/robfig/cron/v3` — Cron scheduler
- `github.com/spf13/viper` + `gopkg.in/yaml.v2` — Configuration

### Testing

- Backend tests use Go's standard `testing` package. Run with `go test ./...`.
- Frontend uses ESLint + TypeScript type checking (`pnpm lint && pnpm typecheck`).
- The `make check` command runs both.
